# Claude Code Antileak Hooks：源码阅读指南

工具事件先检查即将写入的内容，Git 事件再检查实际提交和推送。两层调用同一个策略引擎；名单或执行依据不足时必须与“检查通过”区分。

本指南采用 Lite 包加代码地图，聚焦 **Write/Edit 工具事件到本地策略 content 判定与拒绝结果**。Git 签名密码学验证、远端提交枚举、历史重签豁免、名单网络刷新和安装脚本仅索引，不作完整安全审计；没有安装或更改任何安全钩子。

## 运行与验证

运行环境为 Bash、Python 3、Git 与 OpenSSH。需要先按原有部署文档准备安装路径、名单来源和缓存，不能把源码目录当作已安装环境。安装后的自检入口：

```sh
python3 policy/doctor.py
```

该脚本报告实际安装状态，未安装或配置不全时会出现 FAIL/DEGRADED；不能把文档构建当作护栏自检通过。原有操作手册保留安装和刷新流程，本轮不执行。

这里给出的业务命令来自现有源码或脚本；本轮只执行文档结构校验与站点构建，没有运行业务测试、安装钩子、停止服务或部署。测试文件的存在表示可检查的验证意图，不表示本轮通过。

## 文档站

文档站采用 VitePress 默认主题，依赖与业务项目分开安装。默认输出 `docs-site/.vitepress/dist/`；独立核验可在构建命令后加 `-- --outDir <仓库外绝对目录>`。指南正文只维护 `repo-docs/`，站点通过 include 读取；网页中的仓库源码链接显示为精确文件路径，不复制源码或本机资源。

```sh
pnpm --dir docs-site install --frozen-lockfile
pnpm --dir docs-site run docs:dev -- --host 127.0.0.1
pnpm --dir docs-site run docs:build
```

独立网页构建会把文档目录之外的仓库链接显示为精确文件路径，避免产生失效跳转；原始 Markdown 仍保留可核对的源码链接。站点只发布指南，源码和本机资源不会随文档打包。
