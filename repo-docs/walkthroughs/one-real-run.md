# 一次工具写入怎样得到策略判定

Agent 准备写文件时，先检查即将写入的内容，能够在内容进入仓库前提示风险。这个快速入口必须在工具超时前完成，因此不能把网络刷新放进同一次工具事件。本页只解释本地 content 路径；不会宣称它能阻止所有本机绕过。

这条用户操作的输出是允许继续或明确拒绝。难点是工具检查必须快速返回，同时不能把无法检查或宿主权限确认误当作通过。

## Step 1: 从工具事件取出真正的新增内容

工具包装读取事件 JSON，按 `content`、`new_string` 或 `new_source` 取待写文本，路径只用于定位提示。无内容时安静退出；无效 JSON 会按拒绝处理，不能把解析失败当作空内容。

[内容包装](../../hooks/forbid-content.sh)覆盖 Write、Edit、NotebookEdit。临时文件装载的是工具事件中的内容，不是任意读取用户工程的完整文件，因此这一步不能证明所有现有文件都已审计。

## Step 2: 在部署配置下运行同一个引擎

包装通过[公共辅助](../../hooks/_lib.sh)定位已安装的策略引擎，调用 `check.py content`，不带 `--net`。仓库里的默认路径是部署模板，bootstrap 会按安装位置改写；直接在源码目录调用可能因缺配置而失败。

引擎读取静态模式和动态私有名单缓存。缓存缺失、损坏或过期会得到 error，不能冒充“没命中”。需要更新名单时由独立维护操作刷新；快速工具路径自身不联网。[策略入口](../../policy/check.py)中的 `full_check`、`private_check` 和 `main` 可逐段核对。

## Step 3: 区分通过、违规与检查错误

```text
工具事件 JSON → 提取新增文本 → 本地 content 检查
  pass       → exit 0，安静退出
  violation  → deny JSON + exit 2
  error      → deny JSON + exit 2
```

这是源码控制流示意，不是本轮执行日志。规则包括私有名称、内容卫生和凭据形态等；文档不列真实禁词样例或私有名单。引擎输出三态，包装只把精确 `pass` 当作通过。凭据命中提示按引擎规则脱敏，不能把完整命中值写回日志或会话。

## Step 4: 通过保持安静，拒绝给出可处理原因

通过时不输出 `permissionDecision=allow`，避免把检查通过误当作跳过宿主权限确认。拒绝时包装输出 deny JSON 并以 2 退出；输入解析失败也走拒绝路径。引擎三态与宿主事件退出码不同，排错时要同时看两层。

如果工具进程被宿主超时终止，包装可能来不及返回决定，所以快速路径不联网。实际 Git 钩子再次审查真实提交与推送，并可显式启用名单刷新；它们不等同于工具事件里待写文本的检查。完整安装和事件模式见原有部署手册。

## Step 5: 验证边界： 在已安装环境核对，不把自检当行为测试

```sh
python3 policy/doctor.py
python3 policy/check.py content <中性测试文件>
```

第二条需要安装配置与新鲜名单，文件内容不得包含真实秘密。预期只有 `pass` 返回 0；违规或检查错误非 0。还应独立检查无效事件 JSON 是否被包装拒绝、通过是否保持安静。这些是可复核的检查点，本轮没有运行或新增测试套件，也没有调用安装、名单刷新或 Git 写操作。

doctor 会检查用户设置、Git 钩子接线和缓存，但其 Overall 输出不能替代真实拦截回归，更不能证明本机控制者无法绕过。
